Lesson 17: HTML Validation and Professional Coding

Learn to write clean, accessible HTML, validate your markup and review a professional pre-publishing checklist.

🎯 What You Will Learn

  • How to check the basic structure of an HTML document.
  • How to write clean, readable and consistently indented code.
  • Why semantic elements, labels and alternative text matter.
  • How browser developer tools and HTML validators help find issues.
  • A final checklist before publishing a web page.

1. Start with a Valid HTML Document

A standard HTML document includes a doctype, an html element, a head section and a body section. Set the document language and include character encoding and viewport metadata.

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport"
        content="width=device-width, initial-scale=1.0">
  <title>My Web Page</title>
</head>
<body>
  <h1>Welcome</h1>
  <p>My first page.</p>
</body>
</html>

2. Write Clean and Readable Code

  • Indent nested elements consistently.
  • Use lowercase element and attribute names.
  • Quote attribute values.
  • Use meaningful names for id and class values.
  • Close elements where required and avoid accidental nesting errors.
  • Keep CSS and JavaScript in separate files for larger projects.
  • Write comments that explain why something is done, not every obvious line.
<main>
  <section>
    <h2>About Us</h2>
    <p>We help learners grow.</p>
  </section>
</main>

3. Accessibility and Forms Checklist

  • Give meaningful images useful alt text.
  • Connect each form label to its input using matching for and id.
  • Use suitable input types such as email, password and date.
  • Use headings in a logical order.
  • Use buttons for actions and links for navigation.
  • Make sure controls can be understood and used with a keyboard.
<form>
  <label for="email">Email address</label>
  <input id="email" name="email"
         type="email" required>
  <button type="submit">Submit</button>
</form>

4. Validate and Test Your HTML

Run your page in more than one browser size. Test links, forms, images and buttons. Check the browser console for errors. You can also use the official Nu HTML Checker to identify markup problems.

Open the Nu HTML Checker

Validation tools can find many markup errors, but they cannot decide whether your page is useful, clear or accessible. Always review the page yourself.

5. Final HTML Project Checklist

  • Document starts with <!DOCTYPE html>.
  • HTML element has the correct lang attribute.
  • Head includes charset, viewport and a meaningful title.
  • Content uses semantic structure.
  • Images have appropriate alt text and working paths.
  • Forms have labels and suitable input types.
  • Links and buttons work as expected.
  • Page is readable on mobile and desktop.
  • No unnecessary empty elements or duplicate IDs.

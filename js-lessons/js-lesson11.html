Lesson 11: Scope and Hoisting

Understand where variables can be accessed and how JavaScript handles declarations before code execution.

Part 2 – Core JavaScript

1. What is Scope?

Scope defines the area of a program where a variable or function can be accessed.

In simple words, scope decides where you can use a variable in your JavaScript code.

Why is Scope Important?

  • It controls variable accessibility.
  • It prevents unwanted variable conflicts.
  • It helps organize code.
  • It makes programs easier to understand.
let student = "Aarav";

function showStudent() {
  console.log(student);
}

showStudent();

Output:

Aarav

The variable student is accessible inside the function because it is declared outside it in the global scope.

2. Global Scope

A variable declared outside all functions and blocks has global scope.

It can generally be accessed from anywhere in the same script.

let course = "JavaScript";

function showCourse() {
  console.log(course);
}

showCourse();

console.log(course);

Output:

JavaScript
JavaScript
Remember: Global variables should be used carefully. Too many global variables can make code difficult to manage.

3. Function Scope

Variables declared with var, let, or const inside a function are accessible within that function, but not directly outside it.

function calculateTotal() {
  let price = 500;
  let quantity = 2;

  console.log(price * quantity);
}

calculateTotal();

// This will cause an error:
// console.log(price);

Output:

1000

The variables price and quantity belong to the function scope.

4. Block Scope

A block is a section of code written inside curly braces { }.

Variables declared with let and const inside a block are accessible only within that block.

{
  let name = "Nainsi";
  const age = 24;

  console.log(name);
  console.log(age);
}

// These variables cannot be accessed here.

Output:

Nainsi
24

What about var?

var does not follow block scope. It is function-scoped instead.

{
  var city = "Patna";
  let country = "India";
}

console.log(city);

// console.log(country); // Error

Output:

Patna
Key Point: let and const follow block scope, while var does not.

5. Lexical Scope

Lexical scope means that an inner function can access variables from its outer function where it is written.

function outerFunction() {
  let message = "Welcome to SkillSaathi";

  function innerFunction() {
    console.log(message);
  }

  innerFunction();
}

outerFunction();

Output:

Welcome to SkillSaathi

The inner function can access message because it is defined inside the outer function.

6. Scope Chain

When JavaScript cannot find a variable in the current scope, it looks in the outer scope. This search continues until it finds the variable or reaches the global scope.

let country = "India";

function outer() {
  let state = "Bihar";

  function inner() {
    let city = "Patna";

    console.log(city);
    console.log(state);
    console.log(country);
  }

  inner();
}

outer();

Output:

Patna
Bihar
India

Here, the inner function accesses variables from its own scope, outer function scope, and global scope.

JavaScript searches from the nearest scope outward. It does not search from an outer function into an inner function's local variables.

7. What is Hoisting?

Hoisting is JavaScript's behavior of processing declarations before executing the code in their scope.

Because of hoisting, some variables and functions can be referenced before their declaration appears in the code. However, their behavior depends on how they are declared.

console.log(myName);

var myName = "Aarav";

Output:

undefined

JavaScript processes the var declaration before execution, but the assignment happens at its original position.

Hoisting does not mean JavaScript physically moves your code to the top. It describes how declarations are handled during execution setup.

8. Hoisting with var

Variables declared using var are hoisted and initialized with undefined.

console.log(score);

var score = 90;

console.log(score);

Output:

undefined
90

This is conceptually similar to:

var score;

console.log(score);

score = 90;

console.log(score);

The declaration is processed first, but the value is assigned later.

9. Hoisting with let and const

Variables declared using let and const are also hoisted, but they are not initialized with undefined.

Accessing them before their declaration results in a ReferenceError.

console.log(age);

let age = 24;

Result:

ReferenceError: Cannot access 'age' before initialization

Temporal Dead Zone (TDZ)

The period between entering a scope and the point where a let or const variable is initialized is called the Temporal Dead Zone.

{
  // TDZ starts here

  // console.log(city); // ReferenceError

  let city = "Patna";

  console.log(city);
}

Output:

Patna
Remember: Always declare let and const variables before using them.

10. Function Hoisting

Function declarations are hoisted with their function body. This means you can call a function before its declaration in the same scope.

greet();

function greet() {
  console.log("Hello, learner!");
}

Output:

Hello, learner!

Function Expressions

Function expressions behave differently. The variable declaration may be hoisted, but the function assignment is not available before its execution.

// This will cause an error:
sayHello();

var sayHello = function() {
  console.log("Hello!");
};

Here, sayHello is initially undefined, so trying to call it before assignment produces a TypeError.

Function declarations can be called before their declaration. Function expressions should be used only after they have been assigned.

11. Practical Examples

Example 1: Global and Local Scope

let school = "SkillSaathi";

function showDetails() {
  let student = "Meera";

  console.log(school);
  console.log(student);
}

showDetails();

Output:

SkillSaathi
Meera

Example 2: Block Scope

let marks = 80;

if (marks >= 40) {
  let result = "Pass";
  console.log(result);
}

console.log(marks);

Output:

Pass
80

Example 3: Function Hoisting

displayMessage();

function displayMessage() {
  console.log("Keep learning JavaScript!");
}

Output:

Keep learning JavaScript!

Asynchronous JavaScript

Understand how JavaScript handles tasks that take time without blocking the entire program.

Lesson 21 of 25

1. Introduction to Asynchronous JavaScript

JavaScript normally executes code one statement at a time. But some tasks take time, such as waiting for a timer, responding to a user action, or reading data from a browser API.

Asynchronous JavaScript allows certain operations to complete later while the rest of the program continues running.

Simple meaning: Asynchronous programming means starting a task and allowing other code to continue while that task is waiting.

Examples of time-consuming tasks

  • Waiting for a timer.
  • Responding to a button click.
  • Reading or writing browser data.
  • Receiving information from an external source.

2. Synchronous vs Asynchronous Code

Synchronous code

Synchronous code runs line by line. Each statement waits for the previous statement to finish.

console.log("First");
console.log("Second");
console.log("Third");

Output:

First
Second
Third

Asynchronous code

Some operations are scheduled to happen later. JavaScript can continue executing the next statements in the meantime.

console.log("First");

setTimeout(function(){
    console.log("Second");
}, 2000);

console.log("Third");

Output:

First
Third
Second
The timer schedules the callback for later. It does not stop the next line from running.

3. Blocking and Non-Blocking Code

Blocking code

Blocking code prevents the next operation from continuing until the current operation finishes.

console.log("Task 1");

// A long-running operation can block execution.

console.log("Task 2");

Non-blocking code

Non-blocking operations allow JavaScript to continue with other work while waiting for a scheduled task.

console.log("Start");

setTimeout(function(){
    console.log("Delayed task");
}, 2000);

console.log("Continue working");
A long-running synchronous loop can still freeze the browser. Asynchronous programming does not automatically make every operation faster.

4. JavaScript Execution and Call Stack

JavaScript uses a Call Stack to keep track of which function is currently running.

When a function is called, it is added to the stack. When it finishes, it is removed.

function first(){
    console.log("Inside first");
}

function second(){
    first();
    console.log("Inside second");
}

second();

Output:

Inside first
Inside second

How the Call Stack works

  1. The global code starts executing.
  2. The function second() is called and enters the stack.
  3. Inside it, first() is called and enters the stack.
  4. first() finishes and leaves the stack.
  5. second() finishes and leaves the stack.

5. setTimeout()

setTimeout() schedules a function to run after a specified delay.

Syntax

setTimeout(function, delay);

Example

console.log("Hello");

setTimeout(function(){
    console.log("This runs later");
}, 2000);

console.log("Welcome");

The delay is measured in milliseconds.

  • 1000 milliseconds = 1 second
  • 2000 milliseconds = 2 seconds
  • 5000 milliseconds = 5 seconds

6. setInterval()

setInterval() repeatedly executes a function after a fixed time interval.

Syntax

setInterval(function, interval);

Example

let count = 1;

let timer = setInterval(function(){
    console.log(count);
    count++;
}, 1000);

This example prints a new number every second.

7. clearTimeout()

clearTimeout() cancels a timeout before its scheduled callback executes.

let timer = setTimeout(function(){
    console.log("This message will not appear");
}, 3000);

clearTimeout(timer);

8. clearInterval()

clearInterval() stops a repeating interval.

let count = 0;

let timer = setInterval(function(){
    count++;
    console.log(count);
}, 1000);

// Stop the repeating task
clearInterval(timer);
Remember:
  • clearTimeout() cancels a scheduled one-time callback.
  • clearInterval() stops a repeating callback.

9. Callback Functions

A callback is a function passed as an argument to another function. The receiving function can call it when needed.

function greet(name, callback){
    console.log("Hello " + name);
    callback();
}

function welcome(){
    console.log("Welcome to SkillSaathi!");
}

greet("Student", welcome);

Output:

Hello Student
Welcome to SkillSaathi!

Callbacks are useful in asynchronous operations because they allow us to specify what should happen when a scheduled task is ready to run.

function showMessage(callback){
    setTimeout(function(){
        callback();
    }, 2000);
}

showMessage(function(){
    console.log("Task completed!");
});

10. The Event Loop

The Event Loop helps JavaScript decide when scheduled callbacks can run.

It checks whether the Call Stack is empty and whether a callback is ready in the relevant queue.

Important parts

  • Call Stack: Keeps track of currently executing functions.
  • Web APIs: Browser-provided features that handle timers and other browser tasks.
  • Callback Queue: Holds ready callbacks waiting for the Call Stack.
  • Event Loop: Checks the stack and coordinates when queued callbacks can run.

Basic execution flow

JavaScript Code
      |
      v
  Call Stack
      |
      v
  Browser APIs
      |
      v
 Callback Queue
      |
      v
   Event Loop
      |
      v
  Call Stack (when empty)
This is a simplified introduction. JavaScript also has a separate microtask queue, which we will explore when learning Promises.

11. Web APIs and Callback Queue

Browsers provide Web APIs that JavaScript can use for tasks such as timers and user interactions.

When a timer finishes, its callback becomes eligible to run. It waits until the Call Stack is clear before JavaScript executes it.

console.log("A");

setTimeout(function(){
    console.log("B");
}, 0);

console.log("C");

Output:

A
C
B

Even with a delay of zero milliseconds, the callback does not interrupt the current synchronous code.

12. Understanding Execution Order

Let's understand the order using another example.

console.log("Start");

setTimeout(function(){
    console.log("Timer 1");
}, 1000);

setTimeout(function(){
    console.log("Timer 2");
}, 500);

console.log("End");

Expected output:

Start
End
Timer 2
Timer 1

The synchronous statements run first. The timer with the shorter delay becomes ready earlier.

Timer delays are minimum scheduling delays, not guarantees of exact execution time. A busy Call Stack can delay a callback.

13. Practical Examples

Example 1: Delayed greeting

function greeting(){
    console.log("Good morning!");
}

setTimeout(greeting, 2000);

Example 2: Digital counter

let number = 1;

let counter = setInterval(function(){
    console.log(number);
    number++;

    if(number > 5){
        clearInterval(counter);
    }
}, 1000);

Example 3: Stop a timer

let messageTimer = setTimeout(function(){
    console.log("Your time is up!");
}, 5000);

// Cancel it before five seconds
clearTimeout(messageTimer);
